# 砖皮百科 · 页面流程（大框架）

给后续实现 Agent：只定信息架构与页面职责，不改站点代码。视觉见同目录 [画风设计.md](画风设计.md)。

现站是单页：[site/index.html](../site/index.html) + `state.nav` / hash。新流程仍可做同文档内视图切换，但用户感知上是多页。

---

## 1. 总览

```
进入页（双焦点：图鉴 | 上传）
    │  仅此处点击过渡
    ├─ 图鉴 → 选枪页（封面墙，无侧栏，无焚诀）
    │              └─ 点某枪 → 枪种图鉴页（薄枪种侧栏 + 列表/详情）
    └─ 上传 → 上传选择页
                   ├─ 上传新模板 → 现投稿四步
                   ├─ 查看待审 → 只读待审列表（字段同现审核所见）
                   └─ 审批入口 → 密钥登录 → 现审核（可通过/拒绝）
```

**首页按钮：** 选枪页、枪种图鉴、上传选择页及其子页，**左上角「首页」** 一律回到进入页。进入页自身不需要首页钮。

**焚诀 / 入场指南：去掉，不迁移。**  
**枪种教程图（挑选注意事项）：去掉，不迁移。**  
**版本公告、B 站 / UP：去掉，不迁移。** 左下只留两行小字：`Q群:765759268` 与 `大家加群一起玩`。审核入口只走上传页。  
**详情页（对照 GitHub `origin/main` `site/`）：补充图及「＋」、皮肤信息、点赞、评论、投稿心得、lightbox、B/C/D 必须保留。预览未接不等于迁入时删除。**

**过渡：仅进入页两个大图标的点击。** 选枪→枪种、上传三功能之间，直接切视图。

## 2. 页面说明

### P0 进入页（新）

- 两个对等入口 + **短文字解释**（图标必须能瞬间表达功能）。
- 图鉴 → P1；上传 → P4。
- 无侧栏、无封面墙、无投稿按钮。

### P1 选枪页（复用现首页封面墙的数据，换壳）

- 数据：现 `covers.js` / `renderHomeCovers()` 那套启用武器封面。
- **无侧栏。无焚诀。** 只保留选枪入口 + 左上首页。
- 点封面 → P2，并带上该枪种。

### P2 枪种图鉴页（接近现「点进某枪后的列表」）

- **此时才有左侧枪种栏**，只用于切换武器，**不要**「我要投稿」「审核通道」。
- 主区：大枪名 + 品质/材质/颜色筛选 + 皮肤网格 → 点卡片进独立详情。
- **不要**教程图。详情迁入时必须带上：B/C/D、补充图及「＋」、皮肤信息、点赞、评论、投稿心得、lightbox。
- 侧栏换枪 = 仍在 P2，不回 P1。回进入页用左上首页。

### P3 皮肤详情

现详情能力不变（B/C/D、补充图、「＋」上传、皮肤信息、点赞、评论），只是从 P2 进入独立页。补充图上传成功后仍走待审，外人可在 P5 看到。预览阶段详情是简化壳，**同步云端前端时不得丢掉这些板块。**

### P4 上传选择页（新）

三个功能，各一行解释即可：

| 入口 | 去向 |
|---|---|
| 上传新模板 | P6 现投稿流 |
| 查看待审 | P5 只读列表 |
| 审批入口 | P7 密钥审核 |

### P5 查看待审（新，公开只读）

- **所有人可进，无需密钥。**
- **界面像现审核列表**（[site/review.js](../site/review.js) 卡片），**不能**通过、拒绝、改目录名。
- **字段与当前审核员在列表里能看到的一致**（见下节），不要做成「只显示枪名」的精简版。

### P6 上传新模板

沿用 [site/submit.js](../site/submit.js) 四步：推荐构图 → 筛选/枪型 → 查重 → STS 上传。壳换成新画风 + 左上首页。完成后可提示去 P5 看是否已在待审。

### P7 审批入口

沿用 [site/review.js](../site/review.js)：输密钥 → 待审列表 → 通过/拒绝（含目录名编辑）。仅管理员。与 P5 数据同源，P7 多操作。

## 3. 待审公开字段（P5 = 审核所见）

现审核卡片展示如下。P5 **全部展示**；括号内为仅 P7 才有的控件。

**新皮肤投稿**

- 图：A/B/C/D 有则显示；S1–S3 有则显示
- 标题：武器 · 皮肤名
- 标签：品质、材质、颜色
- 心得 `notes`（有则显示）
- 投稿人 `contributor`
- 时间 `createdAt`
- （P7 才有：目录名输入、通过、拒绝）

**补充图 / 玩家共享图**

- 图：共享图（A）
- 标题：为某 `supplementSkinId` / 皮肤名 补充
- 心得、投稿人、时间
- （P7 才有：通过、拒绝；无目录名）

实现注意：现 `GET /api/submissions` 与预览图 `GET /api/uploads/...` **要管理员 token**。P5 需要**公开只读**的待审列表 + 预览（或签名 URL）。**不要**把 approve/reject 放进公开接口。P5 与 P7 展示字段对齐，权限只在写操作上分开。

## 4. 和现站对照

| 现站 | 新流程 |
|---|---|
| 打开即侧栏 + 焚诀 + 封面墙 | 打开即进入页 |
| 封面墙在首页 | 封面墙 = P1，无侧栏、无焚诀 |
| 侧栏一直在 | 仅 P2 有枪种侧栏 |
| 侧栏「我要投稿 / 审核通道」 | 只从进入页 → P4 进入 |
| 审核仅密钥可见待审 | P5 公开看同一套展示字段；P7 才能批 |

## 5. 给实现 Agent 的范围边界

本次文档**不要求**立刻改 UI。真正开工时应：

1. 先搭 P0/P1/P4 空壳与视图切换，再迁封面墙与现列表。
2. 去掉焚诀相关 UI（`#homeGuide` 等），不要藏到别的页。
3. 加公开待审 API + P5；P7 保持 token。
4. 画风按 [画风设计.md](画风设计.md)，不要先做流线。

不在本流程重做：评论协议、OSS 上传协议、构建 worker、武器解析规则。
